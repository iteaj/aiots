# 自动化测试代理

## 核心流程

```
接收变更 → 分析影响范围 → 编译构建 → 分端测试 → 发现问题 → 修复 → 重验 → 报告
```

## 第一步：分析变更影响范围

接到测试任务后，先判断变更属于哪个端：

- **后端 Java**（`*.java` 文件变更）：需要重启应用才能使变更生效
- **管理前端**（`admin-ui/` 下文件变更）：HMR 热更新，无需重启
- **移动端 H5**（`app/` 下文件变更）：HMR 热更新，无需重启
- **跨端变更**（如新增 API + 前端调用）：各端分别验证

## 第二步：编译构建

根据变更类型执行编译：

```bash
# 后端变更：通过 MCP 构建
mcp__idea__build_project

# 前端变更：框架自动 HMR，无需手动构建
```

## 第三步：启动/重启服务

```bash
# 后端变更后需重启
mcp__idea__xdebug_control_session(action=STOP)
mcp__idea__xdebug_start_debugger_session
# 等待启动完成（约15秒）
```

## 第四步：执行测试

根据变更端分别测试：

### 后端测试
1. 通过 curl 调用变更的接口
2. 验证响应结构 `{"code":xxx, "message":"xxx", "data":xxx}`
3. 验证 `code` 为 `1000` 或 `200` 表示成功
4. 同时测试异常场景（无token、参数缺失等）

### 移动端测试
1. 检查 H5 服务是否运行（`localhost:9900`）
2. 检查页面能否加载（curl 返回 HTML）
3. 通过 `/dev/` 代理验证后端连通性

### 管理端测试
1. 检查 Vite 服务是否运行（`localhost:5173`）
2. 通过 `/api/` 代理验证后端连通性

## 第五步：发现问题 → 自动修复

1. 分析错误原因（根据响应信息和调用栈）
2. 修改代码
3. 重新编译构建
4. 重新测试验证
5. 清理测试中临时添加的标记代码

## 第六步：输出报告

```markdown
## 测试报告

### 后端
- ✅ xxx 接口 — 正常
- ❌ xxx 接口 — 失败原因

### 移动端H5
- ✅ 服务正常

### 管理端
- ❌ 服务未运行

### 结论
全部通过 / 待修复: N 项
```
