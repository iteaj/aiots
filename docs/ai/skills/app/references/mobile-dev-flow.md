# 移动端开发流

## 文件命名规范

- **类型声明文件**：`xxx.type.ts`，如 `device.type.ts`
- **接口声明文件**：`xxx.api.ts`，如 `device.api.ts`
- **页面文件**：使用小写 + 连字符，如 `device-list.uvue`
- **组件文件**：使用小写 + 连字符，如 `device-card.uvue`

## 文件目录规范
- **类型声明和接口声明文件(.ts)** `app/pages/{业务模块标识}/xxx/`
- **页面文件(.uvue)** `app/pages/{业务模块标识}/xxx/`
- **页面独立组件(.uvue)** `app/pages/{业务模块标识}/components/`

## 类型和接口声明文件规范

- **字段类型映射**: 比如 int,float,shot,double,byte -> number
- **前后端字段一致性**: 类型声明的字段要和后端的字段保持一致, 包括字段名, 字段类型
- **参数一致性**: 请求参数和响应参数要和后端接口保持一致, 包括字段名，字段类型


## 类型声明和接口声明模板文件强制遵循 [重要]
- 生成的代码需要严格遵循声明模板文件来生产
- 模板文件位置：`references\`
  - **类型模板**：[TypeTemplate.type.ts](./TypeTemplate.type.ts)
  - **接口模板**：[ApiTemplate.api.ts](./ApiTemplate.api.ts)


## 移动端页面草图要求
- 分析每个页面的功能并通过横线、竖线等画出对应的页面草图
- 草图内容需要包括：
  - 页面的分层结构
  - 每一层用的组件和组件布局
  - 组件内容的分层结构和数据内容
  - 在图的右侧用箭头为每一层加上简短说明，标注能用弹性布局的地方
- 使用弹性布局（cl-row和cl-col）方便自适应不同屏幕尺寸
- 对页面、组件、数据内容的分层结构进行说明并附上使用的组件
- 页面有其他容器（tabs标签、ActionSheet操作面板、Popup弹窗等），将每个容器单独画出来并说明

## 移动端页面开发流程

### 1. 创建页面文件
- **文件路径**：`app/pages/{业务模块标识}/{页面名}.uvue`
- **页面后缀**：必须使用 `.uvue`
- **注册要求**：在 `pages.json` 中注册页面路由
- **子包注册要求**: 底部导航栏没有的页面需要分包, 在`pages.json`的`subPackages`节点下注册

### 2. 页面开发要求
- 可滚动内容必须在 `scroll-view`、`list-view`、`waterflow` 等滚动容器中
- UI 优先使用 `cool-ui` 组件库，没有的组件再考虑 uni-app x 内置组件
- 使用弹性布局时优先使用 `cl-row` 和 `cl-col` 组件
- 页面中调用接口并完成数据展示逻辑

### 3 接口路径前缀
- 移动端接口统一使用 `/m` 前缀
- 示例：`/m/xxx/list`
