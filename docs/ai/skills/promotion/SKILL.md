# 平台推广文案技能

## 生成流程

调用此技能时，按以下步骤执行：

### 第一步：确认类型

询问用户要生成**推广文案**还是**广告文章**。

如用户未明确说明，先展示两者区别让用户选择：
- **推广文案** — 公众号推文、技术文章、案例故事，用于内容营销建立信任
- **广告文章** — 朋友圈短文案、产品介绍页、海报，用于直接转化

### 前置检查：查重

确定类型和话题后，先到对应目录下查看是否已存在同话题文件：
- **推广文案** → `E:\营销文案\aiots\推广文案\`
- **广告文章** → `E:\营销文案\aiots\广告文章\`

如已有相同话题的文章，询问用户是重新生成还是跳过。

### 第二步：确认受众

确认目标读者是谁：
- **工厂负责人/老板** — 关注降本增效
- **技术负责人/CTO** — 关注架构和扩展性
- **系统集成商/SI** — 关注交付速度和利润

### 第三步：选定内容类型

根据第一、二步确定具体形式（公众号推文 / 技术文章 / 案例故事 / 社交媒体等），参考对应模板编写。

### 第四步：自检

对照自检清单逐项复核后输出。

### 第五步：插入平台链接

在文章末尾追加平台信息：

```
---
开源地址：https://www.gitee.com/iteaj/iboot
平台官网：https://www.iteaj.com
演示地址：https://vip.iteaj.com
```

### 第六步：生成文件

将最终文案保存为 `.md` 文件：
- **推广文案** → 放入 `E:\营销文案\aiots\推广文案\` 目录
- **广告文章** → 放入 `E:\营销文案\aiots\广告文章\` 目录

文件名格式：`日期-功能点话题.md`，话题用中文，如 `2026-06-15-告警与指标分离.md`。

格式要求：
- 纯 Markdown 格式，不使用特殊语法
- 标题用 `#` 和 `##`，段落用空行分隔
- 图片用标准 `![](url)` 格式
- 不嵌入平台专有标签（不依赖微信公众号、今日头条等平台特有语法），保持通用可移植

## 平台定位

AI 驱动的工业物联网平台，**模型驱动而非代码驱动**——配配置不写代码，就能对接设备、采集数据、设置告警、生成界面。

## 核心卖点

每条卖点按"场景 → 痛点 → 效果"组织：

1. **零代码接入设备** — 传统 IoT 项目 80% 的时间花在写驱动和调试协议上。平台内置 Modbus、PLC、OPC UA、MQTT、IEC104 等主流工业协议驱动，物模型配配置即可完成设备接入。**一台设备从接线到出数据，按小时计算。**

2. **告警与指标分离** — 偏离正常就告警，告警列表很快被"噪音"淹没。平台把告警和指标分开：阈值超标才告警入库推送，状态标签（偏高/偏低/正常）只显示在前端不扰人。**告警用来找人处理，指标用来快速看数据。**

3. **脚本引擎内嵌数据管道** — 总有非标需求（格式转换、计算、联动逻辑）。平台在采集、解析、联动三个环节内置 JS 脚本引擎，非标需求页面写脚本解决，**不用改后端代码、不用重新发布。**

4. **一次配置，多端适配** — 物模型配好后，PC 管理端和移动端 App 的界面自动适配。**不用为每个端单独开发界面，减少 60% 的前端工作量。**

5. **工业协议全覆盖，开箱即用** — Modbus RTU/TCP、PLC（西门子/三菱/欧姆龙）、OPC UA、MQTT、DTU、IEC104、HTTP 等主流协议均已内置，**新协议可基于 SPI 接口扩展。**

## 目标受众与策略

| 受众 | 核心关注 | 文案策略 |
|------|---------|---------|
| 工厂负责人/老板 | 降本增效、省人省心 | 讲 ROI、减少故障停机、少招人、快响应 |
| 技术负责人/CTO | 架构合理性、可扩展 | 讲模型驱动、零代码接入、技术架构、非侵入 |
| 系统集成商/SI | 交付速度、利润 | 讲复用、一次配置多端适配、减少定制开发量 |

## 推广文案 vs 广告文章

**推广文案（内容营销）** 和 **广告文章（硬推广）** 是两种不同的输出，目的和写法都有区别：

| 维度 | 推广文案 | 广告文章 |
|------|---------|---------|
| 目的 | 教育+建立信任，让读者认可"这个问题该解决" | 触发行动，让读者觉得"我现在就需要" |
| 读者状态 | 被动接触，不急着做决定 | 正有需求，需要快速决策 |
| 形式 | 公众号推文、技术文章、案例故事 | 朋友圈短文案、SEM 落地页、海报 |
| 风格 | 场景先行、讲干货、像分享知识 | 直击痛点、短平快、突出差异化、号召行动 |
| 转化路径 | 阅读 → 认可 → 主动了解 | 看到 → 点击 → 咨询/试用 |

**打个比方：** 推广文案像是和客户聊天建立关系，广告文章像直接问"要不要买"。两者配合使用——推广文案做长线信任建设，广告文章做短线转化收割。

## 内容类型与建议

| 类型 | 归属 | 渠道 | 篇幅 | 风格 |
|------|------|------|------|------|
| 公众号推文 | 推广文案 | 微信 | 1500-2500 字 | 讲案例故事，带数据，配截图 |
| 技术文章 | 推广文案 | 行业媒体/知乎 | 2000-4000 字 | 深度分析，对比传统方案，结构严谨 |
| 案例故事 | 推广文案 | 官网/公众号 | 1000-2000 字 | 背景 → 痛点 → 方案 → 效果，带数据对比 |
| 产品介绍页 | 广告文章 | 官网 | 500-800 字 | 简洁有力，突出差异化 |
| 社交媒体 | 广告文章 | 朋友圈/群聊 | 50-200 字 | 口语化，制造痛点共鸣，引导点击 |

## 推广文案写法

**核心逻辑：选一个平台知识点，围绕它写一篇深度文章。**

### 选题方式

话题来源依次参考以下技能文档：

1. **[功能目录](../features/references/feature-catalog.md)** — 所有功能点清单，每个功能点都有"推广角度"列直接参考选题
2. **[功能设计背景](../features/references/feature-designs.md)** — 功能点的设计背景和解决思路，作为文章"功能背景"环节的素材
3. **[使用教程](../../skills/tutorial/references/)** — 功能的具体配置方法和操作步骤，作为文章"配置方式"环节的素材

### 文章结构

整篇文章围绕所选知识点展开，按以下顺序：

#### 一、功能背景（为什么要这个功能）
- 解释这个功能解决的是什么问题
- 传统做法为什么不行，有什么局限性
- 示例（选"指标"）："传统告警把所有偏离正常的值都入库推送，时间长了告警列表全是噪音，真正需要关注的问题反而被淹没了。所以需要一种方式，让只展示不告警的数据状态和真正需要处理的问题分开。"

#### 二、真实场景（谁在用、在什么情况下用）
- 描述一个具体的角色和场景，让读者能代入
- 不要泛泛说"工厂"，要说"李师傅每天早上要巡检 40 多台注塑机"
- 示例（选"指标"）："车间主任老王的看板上有 60 多个数据点，每个点都在实时跳动——温度、压力、转速、能耗。他需要一眼看出哪些数据偏高了、哪些正常，而不是逐条点开看告警记录。"

#### 三、平台实现（这个功能怎么做的）
- 分两部分讲：
  - **后台设计**：数据结构、触发机制、判断逻辑（如 WarnGrade.indicator 级别不产生告警记录不推送）
  - **前台设计**：移动端和管理端分别怎么展示（如实时数据页面带上状态标签、卡片按颜色分组）
- 这里要体现平台的"设计思路"，不只是罗列功能

#### 四、配置方式（怎么用这个功能）
- 给出具体的配置步骤，让读者能跟着做
- 配图说明（如物模型属性编辑页的"告警/指标配置"选项卡）
- 示例（选"指标"）："编辑物模型属性 → 告警/指标配置 → 选操作符 gt、阈值 50、状态指标填'偏高'、告警级别选'指标' → 保存。采集到 >50 的值时前端自动显示'偏高'标签，不产生告警记录。"

#### 五、效果总结（解决了哪些痛点）
- 拉回开头的场景，形成闭环
- 梳理这个功能帮用户解决了哪些具体问题

### 结尾：开放引导
- 给读者一个低门槛的下一步（免费试用、预约演示）
- 不强迫转化，让感兴趣的人自己行动

### 风格要点
- **像在分享，不是在推销** — 用"我们发现""我们总结了一套方法"的口吻
- **有细节才可信** — 具体的数字、场景、操作过程比空洞的形容词有力
- **知识点就是卖点** — 每篇文章讲透一个功能，读者学到一个知识点的同时也记住了平台的价值
- **一次只讲一个功能** — 一篇文章聚焦一个小功能点（如"指标"），不把告警、采集、配置等杂糅到一起，避免信息过载
- **字数控制** — 1000-1800 字，一个小功能点不需要长篇大论，说清楚背景、场景、实现、配置、效果即可，读者花 3-5 分钟看完

## 广告文章写法

**核心逻辑：痛点 → 方案 → 行动**

### 结构
- 一句话抓住注意力（痛点或反常识陈述）
- 一句话给出方案（平台能做什么）
- 一句话列优势（2-3 个核心差异点）
- 一句行动号召

### 风格要点
- **短** — 能一句话说清楚不说两句
- **直接** — 不绕弯子，直击痛点
- **可验证** — 用具体数据替代"高效""强大"这类空词

## 通用写作规范

1. **用场景开头** — 不先介绍产品，先描述一个真实痛点场景（"工厂设备越来越多，每天巡检要花两小时……"）
2. **少用术语** — 避免"物模型""协议驱动"等内部术语，改用客户能听懂的表达
3. **数据说话** — 有条件时引用数据（接入一台设备从 3 天缩短到 2 小时）
4. **差异化对比** — 与传统方案对比，突出"不用写代码、运维简单、多端适配"
5. **号召行动** — 结尾引导下一步：免费试用、预约演示、联系我们
