# 事件规则

## 事件源

**菜单：事件规则 → 事件源**

事件源分为两种类型：

### 采集器

定义采集哪些设备的数据以及采集频率：

| 配置项 | 说明                                     |
|--------|----------------------------------------|
| 事件类型 | 采集器（采集数据）                              |
| 产品列表 | 选择要采集的**子产品**（只有子产品配置了物模型，才有数据可采）或**直连产品** |
| 设备组 | 只采集选中设备组下的设备                           |
| 频率范围 | 只采集匹配频率标签的事件模型                         |

> **⚠️ 产品选择注意：** 产品列表只能选**子产品或直连产品**不能选父产品（网关产品）。因为只有子产品定义了物模型和事件模型（含频率标签），网关产品没有物模型，选了也采不到数据。

### 执行器

按定时计划执行指定的操作，需配合场景联动使用：

| 配置项 | 说明 |
|--------|------|
| 事件类型 | 执行器（定时触发） |
| 定时策略 | cron 表达式，定义执行时间（如每天 8:00、每 30 分钟） |
| 联动场景 | 选择要触发的场景联动规则 |

**工作原理：** 执行器本身不执行具体操作，它只负责"到点了就通知场景联动"。真正做什么（打开阀门、发送告警、调节参数等）由关联的场景联动规则定义。即**执行器负责"什么时候做"，场景联动负责"做什么"**。

**示例：** 创建一个执行器，定时策略设为每天 8:00，关联一个场景联动规则"打开车间照明"。每天 8:00 执行器触发该规则，照明打开。

## 场景联动

**菜单：事件规则 → 场景联动**

配置自动化规则（如果…就…），例如：

- 如果温度 > 50℃ 且 湿度 < 30% → 触发告警
- 如果湿度 < 30% → 打开加湿器
- 如果设备离线 → 发送短信通知

> **与物模型属性告警的分工：** 
> - **单属性阈值判断**（如温度 > 50℃）已在物模型属性编辑页的"告警/指标配置"中配置，采集时自动触发，无需在此处重复配置
> - **场景联动**负责**多属性组合条件**（如温度 > 50℃ 且 湿度 < 30%）、**指令联动**（条件满足时执行控制指令）以及需要**多个动作**的复杂规则
> - **设备状态告警**（上线/离线）无需配置，平台自动记录
