# 网络组件配置

**菜单：基础信息 → 网络组件**

## 系统角色

网络组件在平台中扮演**通信链路层**的角色，负责为设备提供网络接入入口。它解决的是"平台与设备之间怎么连"的问题：

- **连接管理** — 定义平台与设备之间的网络连接方式（TCP/UDP/MQTT 等协议、IP 地址、端口号）
- **网关承载** — 网关设备需挂载到网络组件下，通过网络组件建立的链路与子设备通信
- **资源隔离** — 不同网络组件相互独立，可按物理网络环境（如不同车间、不同网段）划分通信通道

## 解决的问题

| 问题 | 网络组件的解决方式 |
|------|------------------|
| 设备分布在不同网络环境，如何统一管理连接？ | 按网络环境创建不同的网络组件，每个组件独立管理连接参数 |
| 网关设备下的子设备如何接入平台？ | 网关挂载到网络组件，子设备通过网关间接接入，网络组件统一管理链路 |
| 连接参数（IP、端口）变更影响范围大？ | 修改网络组件配置即可，关联的网关和产品自动生效，无需逐个修改 |
| 如何知道当前有哪些通信通道可用？ | 网络组件列表直观展示所有已配置的通信链路及其状态 |

## 配置步骤

1. 进入 **基础信息 → 网络组件**
2. 新增网关组件，填写 IP、端口等连接信息

> **提示：** 对于内置驱动（Modbus、PLC、OPC UA 等），对应的网络组件已预置，通常无需手动配置。仅在接入自定义网关设备或特殊网络环境时才需要新增网络组件。

## 与其他模块的关系

```
网络组件 ──提供连接通道──→ 协议驱动（驱动通过网络组件的链路与设备通信）
    │
    └──挂载──→ 网关设备（网关通过网络组件连接子设备）
```

- **网络组件 vs 协议驱动**：网络组件负责"怎么连"（TCP/MQTT/串口等连接方式），驱动负责"怎么说话"（协议解析和数据翻译）
- **网络组件 vs 产品**：产品创建时关联网关（网络组件），网关设备通过挂载的网络组件建立通信链路
