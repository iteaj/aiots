# 产品配置与物模型

## 产品类型

**菜单：基础信息 → 产品类型**

对产品进行分类管理，如"传感器"、"执行器"、"控制器"等。一个产品类型下可包含多个产品。

## 产品配置

**菜单：基础信息 → 产品配置**

产品是对同一类型设备的抽象定义。物模型是产品的核心，定义设备的数据结构和交互接口。

### 创建产品

1. 进入 **基础信息 → 产品配置**，点击"新增"
2. 填写产品名称、编号
3. 选择产品类型（若无可先在"产品类型"中新增）
4. 选择关联网关（网络组件）
5. 选择关联的协议驱动
6. 若设备类型为**网关子设备**，还需选择对应的父产品（即该子设备所属的网关产品）
7. 保存

**驱动和产品的关系：** 打个比方，驱动就像一部**手机**，它有打电话、发短信、拍照等能力（指令）。产品就像手机里的一个**App**，它只挑选自己需要的功能来用——导航 App 用 GPS 和定位，拍照 App 用摄像头，但不会去用短信功能。

具体到平台：
1. **驱动提供能力** — 比如 Modbus 驱动知道怎么用 03 指令读寄存器、06 指令写寄存器，但它不知道这些数据代表什么
2. **产品挑选使用** — 温度传感器产品选用 Modbus 驱动后，在事件模型中选择 03 指令并绑定到 temperature 属性，在功能模型中选择 06 指令用来下发校准值

同一个驱动可以服务于多个产品（Modbus 驱动同时给温度传感器和压力传感器用），同一个产品换用不同驱动就能对接不同协议的设备。

> **⚠️ 重要：物模型只配置在有数据的产品上**
>
> 三种产品类型中，物模型的有无：
>
> | 产品类型 | 对应设备 | 是否有物模型 |
> |---------|---------|------------|
> | **直连产品** | 直连设备（直接联网、产生数据） | **有** |
> | **子产品** | 网关子设备（通过网关联网、产生数据） | **有** |
> | **父产品（网关产品）** | 网关设备（不产生数据、只转发） | **无** |
>
> 原因：只有真正产生数据的设备才需要定义属性、功能模型和事件模型。网关设备本身不产生业务数据，只做协议转发，所以它的产品不需要配置物模型。
>
> 创建产品时对照上表确认类型：
> - **直连产品 / 子产品** — 需配置物模型，创建时选择关联的协议驱动
> - **父产品（网关产品）** — 不配置物模型，创建时选择关联网关（网络组件），不需要选择协议驱动
>
> 后续配置采集器时，产品列表只能选**直连产品**或**子产品**，不能选父产品（选了也没数据可采）。
>
> **🔄 针对内置驱动的简化流程：**
>
> 对于系统已内置的驱动（Modbus、PLC、OPC UA、MQTT 等），以下两项平台已默认配好，**不需要手动添加**：
> - **网络组件** — 对应内置驱动的网络组件已预置
> - **网关产品（父产品）** — 已为网关设备创建了一款默认的网关产品
>
> 所以接入一款支持内置驱动的设备时，默认只需要：
> - **网关子设备** — 新增一个**子产品**（配置物模型），然后在子产品下创建设备
> - **直连设备** — 新增一个**直连产品**（配置物模型），然后创建设备
>
> 网络组件和网关产品都用默认的即可，无需额外配置。

### 配置物模型属性

物模型属性定义设备会上报哪些数据（如温度、湿度、开关状态等）：

| 配置项 | 说明 | 示例 |
|--------|------|------|
| 属性名称 | 数据点的中文名 | 温度 |
| 标识符 | 唯一标识 | temperature |
| 数据类型 | 数据类型 | float |
| 单位 | 数据单位 | ℃ |
| 读写类型 | 是否可写 | 只读 / 可读可写 |
| 序号 | 排序值，越小越靠前 | 0 |

数据类型分为**基本类型**（string、boolean、byte、short、int、long、float、double、date）和**容器类型**（json、group、bit）。

容器类型用于处理事件接口返回的复杂值，将其展开为多个子字段。容器类型的属性本身不会显示在历史数据和实时数据列表中，展示的是展开后的子字段。配置容器类型的模型属性时，需要在其下方的"属性值配置"列表中配置子字段：

| 容器类型 | 用途 | 路径说明 |
|---------|------|---------|
| **json** | 事件返回 JSON 对象时，拆解为多个子字段 | 填写 JSON 路径如 `$.data.temp` |
| **bit** | 一个数值的不同比特位代表不同含义时，按位拆解 | 填写比特位位置如 `1`、`4-6` |
| **group** | 将多个相关属性归为一组 | 无需路径 |

配置子字段时，通过下拉框选择已有的基础类型属性来完成绑定——该子字段引用哪个属性，就继承那个属性的数据类型和其他配置。

**属性字典配置：** 对于枚举型属性（如开关状态），可在"属性值配置"列表中配置字典：名称填"开"、值填 true；名称填"关"、值填 false。后续功能模型的下行配置与此属性绑定时，会自动将控制接口拆分为"控制→开"和"控制→关"两个操作，操作员直接点击即可，无需手动填写 true/false。

**告警/指标配置：** 编辑物模型属性时，新增了"告警/指标配置"选项卡，用于对该属性配置单属性告警规则和状态指标。每次该属性采集到新值时，平台自动判断是否满足告警条件。配置项如下：

| 配置项 | 说明 | 示例 |
|--------|------|------|
| 启用告警 | 开启后该属性参与告警判定 | 开/关 |
| 操作符 | 触发条件，可选：大于(gt)、大于等于(gte)、小于(lt)、小于等于(lte)、等于(eq)、不等于(neq)、包含(contain)、在范围内(in)、介于(between) | gt |
| 阈值 | 与操作符配合使用的触发阈值 | 50 |
| 状态指标 | 当告警触发时显示的状态标签，用于标明当前值所处的状态（如偏高、偏低、过高、过低、正常、危险等） | 偏高 |
| 告警级别 | 可选值：严重(fatal)、紧急(urgent)、告警(warn)、通知(notice)、解除(normal)、状态(status)、**指标(indicator)** | 告警 |
| 扩展配置 | JSON 格式，预留用于未来扩展 | `{"duration": 30}` |

**告警级别说明：** 级别由 WarnGrade 枚举定义，其中：
- **指标(indicator)** — 特殊级别，选择后**不会入库告警记录**，**不会推送告警消息**，仅用于在前端显示属性值的状态标签（如正常/偏高/过低等），适合无需告警但希望直观展示数据状态的场景
- **其他级别**（严重/紧急/告警/通知/解除/状态）— 触发时正常入库告警记录并推送消息

**配置示例：** 为温度属性配置"温度过高告警"——
- 操作符选择 `gt`（大于）
- 阈值填 `50`
- 状态指标填"过高"
- 告警级别选"告警"
- 当设备上报温度 > 50℃ 时，产生告警记录并推送消息

**纯指标展示示例：** 为温度属性仅显示状态标签——
- 操作符选择 `gt`（大于）
- 阈值填 `50`
- 状态指标填"偏高"
- 告警级别选"指标(indicator)"
- 当设备上报温度 > 50℃ 时，前端显示"偏高"标签，不产生告警记录，不推送消息

> **与场景联动的关系：** 此处的告警/指标配置仅针对**单属性**的阈值判断。如果告警条件涉及多个属性组合判断（如温度 > 50℃ 且湿度 < 30%），仍需要在**场景联动**中配置。设备在线/离线状态的告警无需配置，平台自动记录。

### 配置物模型接口

物模型接口分为两类：**功能模型**和**事件模型**。

**功能模型**用于向设备下发控制指令（如开关控制、参数设置），由平台主动发起：

| 配置项 | 说明 | 示例 |
|--------|------|------|
| 接口名称 | 指令中文名 | 开关控制 |
| 标识符 | 指令标识 | switchControl |
| 指令 | 选择驱动提供的指令，选定后自动确定上下行参数 | 03 读保持寄存器 |
| 输入参数 | 指令携带的参数 | onOff: bool |
| 输出参数 | 指令返回的数据 | result: int |
| 序号 | 排序值，越小越靠前 | 0 |

**事件模型**用于获取设备数据，包括平台主动采集和设备主动上报两种方式。

对于 PLC、Modbus 等按点位采集的协议，平台采集到数据后需要与物模型属性绑定。通过在事件模型的**上行配置**中，输入 `@` 会弹出当前产品的模型属性列表，选择对应属性即完成绑定——该事件采集的值会自动写入所选属性。

| 配置项 | 说明 | 示例 |
|--------|------|------|
| 接口名称 | 事件中文名 | 温度上报 |
| 标识符 | 事件标识 | temperatureReport |
| 指令 | 选择驱动提供的指令，选定后自动确定上下行参数 | 03 读保持寄存器 |
| 输出参数 | 上报的数据 | value: float |
| 上行配置 | `@`选择要绑定的模型属性 | @temperature |
| 频率标签 | 采集频率标签，配合事件源实现不同属性不同采集频率 | 1s、5s、10s |

**操作方式：** 在产品列表点击"物模型"按钮，进入编辑页分别配置属性、功能模型和事件模型。

**指令和模型接口的关系：** 指令是驱动提供的底层协议操作（如 Modbus 的 03 读保持寄存器），模型接口是业务层面的定义（如"温度读取"）。一个模型接口选择一个指令，告诉驱动"用这个指令来采集或控制"；同一个指令可以被多个模型接口复用。简单说就是**驱动提供指令，模型接口挑选用哪个**。

### 物模型计算属性

设备上报的通常是原始值（如脉冲数），但业务需要的是换算后的值（如流量）。采集完成后自动执行 JS 脚本，通过 `methods.getValue(属性标识符)` 读取已采集的值，计算后通过 `methods.updateValue(属性标识符, 值)` 将结果写入另一属性。

适用于统计汇总、系数换算、累加等场景。例如：采集到脉冲数 1500，乘以标定系数 0.0102，将结果 15.3 写入流量属性。

关键在于它和**数据解析**的区别：

- **数据解析（值解析器）** — 发生在采集时，把设备上报的原始字节转为可读值（比如 Modbus 两个寄存器字节拼成一个 float）
- **计算属性** — 发生在采集后，对已经解析好的值做二次计算（比如脉冲数 × 系数 = 流量）

### 功能模型控制状态

一个产品可能定义多个功能模型接口（开关控制、参数设置、模式切换等），但移动端设备列表或详情页展示空间有限，无法全部展示。标记为"控制状态"的接口会被识别为核心操作入口，在空间受限的场景下优先展示，用户可直接操作，无需进入二级页面。

编辑功能模型接口时开启"控制状态"开关即可生效。
