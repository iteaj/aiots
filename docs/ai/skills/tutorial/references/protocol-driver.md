# 协议驱动配置

**菜单：基础信息 → 协议驱动**

## 系统角色

协议驱动在平台中扮演**设备通信层**的角色，是整个物联网平台与物理设备交互的唯一入口。它负责：

- **协议适配** — 屏蔽不同设备协议（Modbus、PLC、MQTT、OPC UA 等）的差异，为上层提供统一的数据读写接口
- **数据翻译** — 将设备的原始报文解析为平台能理解的物模型属性值，同时将平台下发的控制指令翻译成设备能识别的协议命令
- **指令集管理** — 每种驱动注册一套指令集（如 Modbus 的 03 读寄存器、06 写寄存器），产品和物模型通过选择指令来使用驱动能力

## 解决的问题

| 问题 | 协议驱动的解决方式 |
|------|------------------|
| 设备协议种类繁多，每接入一种新设备就要写代码？ | 内置主流协议驱动，接入新设备时选择对应驱动即可，零代码 |
| 不同协议的数据格式不统一，上层业务无法通用处理？ | 驱动将各协议数据统一翻译为物模型属性值，上层业务只关心物模型 |
| 控制指令需要针对不同协议分别开发？ | 驱动提供统一的指令接口，功能模型选择指令即可完成控制，无需关心底层协议细节 |
| 同一类型设备使用不同协议怎么办？ | 产品可以切换关联的驱动，物模型配置不变，实现"换驱动不换模型" |

## 内置驱动列表

平台内置的驱动：

| 驱动 | 适用设备 | 通信方式 |
|------|---------|---------|
| Modbus | Modbus RTU/TCP 设备 | 串口/TCP |
| DTU | DTU 透传模块 | TCP |
| MQTT | MQTT 协议设备 | TCP |
| OPC UA | OPC UA 服务器 | TCP |
| PLC（西门子/欧姆龙/三菱/罗克韦尔/汇川等） | PLC 设备 | TCP |
| Fanuc CNC | 发那科数控机床 | TCP |
| DLT645 | 国家电网电表 | 串口/TCP |
| IEC104 | 电力远动设备 | TCP |
| IEC61850 | 变电站智能设备 | TCP |
| 自定义脚本驱动 | 私有协议设备 | 自定义 |

内置驱动对应的网络组件和网关产品都已预置，接入设备时直接创建直连产品或子产品即可，无需重复配置网络组件和网关产品（详见[产品配置与物模型](./product-config.md)中的说明）。

## 配置步骤

1. 进入 **基础信息 → 协议驱动**
2. 点击"新增"，选择驱动类型
3. 填写驱动参数（端口号、协议参数等）
4. 保存即注册到平台

## 与其他模块的关系

```
协议驱动 ──提供指令集──→ 产品物模型（事件模型/功能模型选择指令）
    │
    └──依赖──→ 网络组件（驱动通过网络组件建立的连接与设备通信）
```

- **驱动 vs 网络组件**：网络组件负责"怎么连"（TCP/MQTT/串口等连接方式），驱动负责"怎么说话"（协议解析和数据翻译）
- **驱动 vs 产品**：驱动提供底层指令能力，产品从中挑选需要的指令来定义采集接口和控制接口

## 驱动的动态配置项

### 设计背景

不同的驱动需要的配置参数各不相同 — 例如 Modbus 需要主机地址和端口，PLC 需要型号和协议类型，MQTT 需要 Broker 地址和主题规则。但平台的产品、设备、网络组件等配置页面是统一的，不可能为每种驱动单独开发页面。

因此平台采用了**动态配置**机制：每个驱动通过代码声明自己需要哪些配置项，平台读取后自动渲染到对应的配置页面中。这样新增驱动时无需修改页面代码，页面天然支持动态添加配置的能力。

### 配置类型与使用场景

驱动通过四个方法提供配置项，分别出现在不同的操作场景中：

| 配置类型 | 方法 | 使用场景 | 说明 |
|---------|------|---------|------|
| **productConfig** | `getProductConfig()` | 新增产品时 | 产品级别的额外参数，如 MQTT 驱动可定义默认主题规则 |
| **gatewayConfig** | `getGatewayConfig()` | 添加网关设备时 | 网关设备的通信参数，如主机地址、端口、PLC 型号等 |
| **deviceConfig** | `getDeviceConfig()` | 添加网关子设备时 | 子设备的协议参数，如 Modbus 字节序、批量采集开关 |
| **networkConfig** | `getNetworkConfig()` | 新增网络组件时 | 网络组件的连接参数，如 DTU 的监听端口、注册码类型 |

> **说明：** 并非每个驱动都有全部四类配置。大多数内置驱动的 `productConfig` 和 `networkConfig` 为空（已预置），用户主要接触的是 `gatewayConfig`（添加网关设备时）和 `deviceConfig`（添加网关子设备时）。
