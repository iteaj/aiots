# AIoTS App 开发 Skill

## 1. Skill 概述

### 1.1 Skill 名称

AIoTS App 开发 Skill

### 1.2 目标

本 Skill 用于指导 Agent 和客户开发者在 **AIoTS** 项目中：

- 正确理解物联网领域模型与业务架构；
- 通过 MCP 接口动态获取实体属性与物模型定义；
- 基于统一的属性体系设计设备列表、详情、控制等页面；
- 遵循 UI 设计规范和组件选型标准；
- 高效完成二次开发和功能扩展。

### 1.3 适用场景

当用户在 AIoTS 项目中提出以下需求时，应启用本 Skill：

- 新增 / 修改设备相关页面（列表、详情、控制面板等）；
- 设计设备组 / 项目 / 空间管理功能；
- 实现设备属性展示、参数配置、指令下发；
- 处理告警、事件、数据可视化等业务；
- 和物联网相关的概念；

### 1.4 非适用场景 / 边界

- 与本项目无关的通用前端教学；
- 后端服务实现细节（MCP 接口由后端团队维护）；
- 不主动创建新的 `.md` / `.txt` / README 等文档文件；
- 不在 skill 或前端代码中静态定义数据结构。

## 2. 项目与领域定位

### 2.1 业务领域

本项目面向两大物联网领域：

| 领域 | 典型场景 | 核心实体示例 |
|------|----------|--------------|
| **工业物联网** | 工厂、园区、农业、水利、城市 | PLC、传感器、网关、电表、水表、摄像头 |
| **智能家居** | 家庭、公寓、酒店 | 灯具、空调、门锁、窗帘、传感器 |

### 2.2 核心设计原则

1. **统一底座，场景差异配置化**
   - 工业物联网与智能家居共用同一套代码底座；
   - 差异通过「设备类型枚举」「物模型配置」「UI 文案」体现，不另起分支。

2. **数据结构动态化**
   - 所有实体属性、物模型属性均通过 MCP 接口动态获取；
   - 前端不静态定义字段结构，保持与后端一致。

3. **客户开发友好**
   - 提供清晰的领域模型和 MCP 接口说明；
   - 客户开发者可快速理解并基于此进行二次开发；
   - AI Agent 可基于规范自动生成代码。

### 2.3 技术栈

| 类别 | 技术 |
|------|------|
| 核心框架 | uni-app x + Vue 3 + TypeScript |
| 构建工具 | Vite（端口 9900） |
| UI 样式 | Tailwind CSS + Cool UI |
| 多语言 | `$t` / `t` 函数 + AI 自动翻译 |

## 3. 领域模型

### 3.1 核心实体关系

```
产品(Product) ──包含──> 物模型(ThingModel)
       │                    │
       │                    ├── 属性(Properties)
       │                    └── 指令集(Commands)
       │
       └──实例化──> 设备(Device) ──归属──> 设备组(Group/Space)
```

### 3.2 表实体说明

| 实体 | 说明 | 关键字段 |
|------|------|----------|
| **产品(Product)** | 设备类型的抽象定义 | productCode、name|
| **设备(Device)** | 产品的具体实例 | name、productCode、groupCode |
| **设备组(Group)** | 空间/组织单位 | name、pid |

### 3.3 设备组层级示例

| 场景 | 层级示例 |
|------|----------|
| 工厂 | 集团 → 工厂 → 车间 → 产线 → 工位 |
| 园区 | 园区 → 楼栋 → 楼层 → 房间 |
| 农业 | 农场 → 区域 → 大棚 → 地块 |
| 智能家居 | 家庭 → 楼层 → 房间 |

## 4. 页面设计规范

## 5. 后端接口开发规范
查阅 `references/backend-api-spec.md`（命名规则、类型生成策略、分页响应结构等）；
### 6.1 整体风格

**物联网科技风**：
- 专业、简洁、高信息密度的界面设计
- 以数据为核心，突出设备状态和关键指标
- 避免过度装饰，强调功能性和可操作性

### 6.2 设计原则

| 原则 | 说明 |
|------|------|
| **简洁高效** | 页面元素精简，信息层级清晰，一眼获取关键信息 |
| **操作极简** | 减少操作步骤，常用功能一键触达，复杂操作分步引导 |
| **状态可视** | 设备状态、告警信息通过颜色、图标直观呈现 |
| **数据驱动** | 以数据展示为核心，图表、数值、趋势一目了然 |
| **响应迅速** | 操作反馈即时，加载状态明确，避免用户等待焦虑 |

### 6.3 页面布局规范

**通用布局结构**：
```
┌─────────────────────────────┐
│  顶部导航栏（可选）          │
├─────────────────────────────┤
│  搜索 / 筛选区域（可选）     │
├─────────────────────────────┤
│  统计概览（可选）            │
├─────────────────────────────┤
│  主体内容区                  │
│  - 列表 / 卡片 / 表单        │
│  - 数据可视化                │
├─────────────────────────────┤
│  底部操作区（可选）          │
└─────────────────────────────┘
```

**布局要点**：
- 顶部导航：使用 `cl-topbar`，标题简洁，右侧放置常用操作
- 搜索筛选：折叠次要筛选项，保留高频筛选入口
- 主体内容：采用卡片式布局，信息分组明确
- 底部操作：固定底部的重要操作按钮，如保存、提交

### 6.4 列表页设计规范

**设计目标**：快速浏览、快速定位、快速操作

**核心要素**：
- 一屏展示足够信息，避免过度滚动
- 关键状态（在线/离线/告警）一眼识别
- 支持快捷操作（滑动、长按、点击）
- 空状态友好提示

**信息密度控制**：
- 列表项高度适中，保证可点击区域
- 每行展示 2-3 个关键字段
- 次要信息通过详情页展开

### 6.5 详情页设计规范

**设计目标**：信息完整、操作便捷、层次清晰

**信息分区**：
- 头部：核心信息（名称、状态、关键数据）
- 中部：分组展示（基本信息、运行数据、配置参数）
- 底部：操作区域（控制按钮、指令下发）

**交互原则**：
- 可编辑字段 inline 编辑或弹窗编辑，减少页面跳转
- 控制操作集中放置，避免分散
- 危险操作二次确认

### 6.6 表单页设计规范

**设计目标**：填写高效、校验即时、错误友好

**设计要点**：
- 字段分组，相关字段就近排列
- 必填项明确标识
- 实时校验，即时反馈
- 支持草稿保存

### 6.7 操作步骤控制

**极简操作原则**：

| 操作类型 | 目标步骤 | 设计策略 |
|----------|----------|----------|
| 查看信息 | 1 步 | 列表点击直达详情 |
| 快捷控制 | 1-2 步 | 列表页/详情页直接操作 |
| 参数配置 | 2-3 步 | 弹窗编辑，保存即生效 |
| 复杂流程 | ≤ 4 步 | 分步引导，进度指示 |

**减少步骤的策略**：
- 默认值智能填充
- 批量操作支持
- 快捷操作入口（长按、滑动）
- 智能推荐（基于场景自动选择）

### 6.8 视觉层次规范

**色彩运用**：
- 主色用于强调和交互
- 状态色严格对应（在线绿、离线灰、告警橙、故障红）
- 背景色区分层次，避免过多颜色干扰

**字体层次**：
- 标题：16-18px，加粗
- 正文：14px，常规
- 辅助信息：12px，灰色

**间距控制**：
- 页面边距：16px
- 卡片间距：12px
- 内容内边距：12-16px

## 7. UI 设计规范

### 7.1 状态颜色规范

| 状态 | 颜色 | 用途 |
|------|------|------|
| 在线 | 绿色（green-500） | 设备在线状态标识 |
| 离线 | 灰色（gray-400） | 设备离线状态标识 |
| 告警 | 橙色（orange-500） | 设备告警状态标识 |
| 故障 | 红色（red-500） | 设备故障状态标识 |
| 未激活 | 黄色（yellow-500） | 设备未激活状态标识 |

### 7.2 告警等级颜色

| 等级 | 颜色 | 说明 |
|------|------|------|
| info | 蓝色 | 提示信息 |
| warn | 橙色 | 警告 |
| error | 红色 | 错误 |
| fatal | 深红 | 严重故障 |

### 7.3 属性类型 → UI 控件映射

| 数据类型 | 推荐控件 | 说明 |
|----------|----------|------|
| string | `cl-input` | 文本输入 |
| int / float | `cl-input-number` / `cl-slider` | 数值输入，结合 range 校验 |
| bool | `cl-switch` | 开关 |
| enum | `cl-select` / `cl-radio` | 单选 |
| date | `cl-select-date` | 日期选择 |
| object | 自定义组件 | 复杂结构 |

### 7.4 样式规范

- 优先使用 Tailwind 类进行布局与样式控制；
- 支持 `dark:` 前缀实现暗色模式；
- 所有文案使用 `t` / `$t` 支持多语言。

## 8. AI 行为约束

### 8.1 必须遵守

1. **先查 MCP 再设计**
   - 涉及实体属性或物模型属性时，必须先调用对应 MCP 接口；
   - 根据返回结果决定字段、类型、控件。

2. **使用统一术语**
   - 产品 / 设备 / 设备组 / 物模型 / 属性 / 指令；
   - 不使用模糊或自创术语。

3. **复用现有组件**
   - 优先使用 Cool UI 组件；
   - 不重复造轮子。

4. **保持与后端一致**
   - 字段名、类型与 MCP 返回保持一致；
   - 不在前端额外定义或转换。

### 8.2 禁止行为

1. **禁止臆造字段**
   - 不允许假设 MCP 中未定义的属性或指令；
   - 例如：直接使用 `temperature`、`status` 而未确认来源。

2. **禁止静态定义数据结构**
   - 不在 skill 或前端代码中写死实体属性、物模型属性的具体字段；
   - 所有结构以 MCP 返回为准。

3. **禁止随意修改核心配置**
   - 不修改 `.cool` 内核、构建配置等；
   - 如需扩展，在允许范围内进行。
