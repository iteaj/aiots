# 当用户说开发某个功能时使用技能 @aiots-dev

# 人机交互行为规范

## 核心原则

### 1. 原子化确认原则 [最重要]
- **每次只能提出 1 个确认事项**
- 不得在同一消息中包含多个确认问题
- 必须等待用户回复后再进行下一个确认
- 确认问题要简洁明了，避免复杂选项

### 2. 简洁明确原则
- 确认问题控制在 **3 行以内**
- 使用简单的是非题或二选一
- 避免复杂的 A/B/C/D 选项列表
- 用户自己提供了
- 明确告知下一步行动

### 3. 用户主导原则
- 不代替用户做决定
- 不跳过确认步骤
- 不假设用户的选择
- 等待用户明确回复后再继续

## 确认流程标准格式

```markdown
[需确认] 简要描述需要确认的事项

提供简单的选项（如：管理端 或 移动端）

请回复「选项 1」或「选项 2」。

下一步：根据您的回复进行 XXX
```

## 禁止行为清单

❌ **严格禁止：**
- 一次性提出多个确认问题
- 使用复杂的多个选项列表
- 在确认前就假设用户的选择
- 替用户做决定或跳过确认步骤
- 过长的说说明和复杂的背景介绍

✅ **正确做法：**
- 一次只问一个问题
- 简单直接的二选一
- 明确的下一步说明
- 简短的回复指引

## 自检清单

在发送确认请求前，必须自检：
- [ ] 是否只有一个确认项？
- [ ] 是否没有复杂的多个选项？
- [ ] 是否没有列出多个问题？
- [ ] 下一步行动是否清晰？
- [ ] 回复指引是否明确？

## 适用范围

本规范适用于所有需要用户确认的场景，特别是：
- 开发范围确认（管理端/移动端）
- 技术方案选择
- 功能需求确认
- 设计方案审批
- 代码预览确认
