# 开发功能时使用aiots-dev技能

> **此规则文件需配合 `aiots-dev` 技能使用**，技能内含完整的CRUD开发流程、代码模板、速查文档等参考资料。

# 人机交互行为规范

## 确认三原则

1. **原子化** — 每次只提1个确认事项，等用户回复后再继续
2. **简洁明确** — 确认问题控制在5行以内，用二选一而非多选项
3. **用户主导** — 不代替用户做决定，不跳过确认步骤，不假设用户选择

## 通用规范

- **先判断基座再开发** — 拿到任务先判断属于哪个开发基座（CRUD/管理端/移动端/驱动/插件），查阅对应流程文档，禁止跳过流程
- **严格遵守规范** — 生成的代码需符合各基座开发流程文档规范
- **后端先于前端** — 前端接口URL、参数、方法与后端保持一致
- **执行自检清单** — 生成代码前必须先通过对应基座的自检清单检查
- **不确定必确认** — 查询不到解决方法时必须和用户确认，**不允许**无中生有
- **新增文件自动加入Git** — 创建新文件后必须 `git add` 加入版本控制

## 数据库变更规范

- **统一补丁文件** — 所有数据库变更写入 `docs/sql/patch.sql`（追加模式）
- **时间标注** — 每次修改添加时间注释：`-- 2026-04-27 添加频率标签字段`
- **完整DDL** — 包含完整的DDL语句和必要注释

## 开发前确认流程

**流程**：思路先行 → 影响评估 → 用户确认 → 分步执行

**确认内容**：
1. 开发目标和范围
2. 技术方案及理由
3. 涉及文件和模块
4. 潜在风险和注意事项
5. 实施步骤和预期结果

# 速查文档优先原则

开发时遇到不确定的用法，**必须先查阅对应基座的速查文档**，仅在速查文档未覆盖时才尝试其他解决方式
